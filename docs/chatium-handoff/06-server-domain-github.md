# 06. Хостинг, домен, Telegram, GitHub

## Хостинг: Vercel уходит целиком

В оригинале: код на **Vercel**, БД и файлы в **Supabase**, письма через **Resend**, крон через **Vercel Cron**. В Chatium **всё это заменяет сама платформа** — деплоя как этапа нет: сохранил файл → код «живой» на серверах Chatium (managed Kubernetes / Postgres / Redis / CDN).

| Роль | Было | Стало (Chatium) |
|---|---|---|
| Хостинг + бэкенд | Vercel | Chatium (встроенно) |
| БД | Supabase Postgres | Heap |
| Файлы | Supabase Storage | Медиасервис |
| Крон | Vercel Cron | Отложенные задачи |
| Письма | Resend | Встроенная авторизация Chatium |

> **Минус — вендор-лок:** код и данные живут внутри Chatium; «забрать на свой сервер» уже не так просто, как с Next.js. Заранее уточните у Chatium экспорт кода и данных.

## Домен (переносим свой домен с сохранением URL)

Аккаунт Chatium всегда доступен на системном домене (`<slug>.chatium.com` / `.ru`); поверх привязывается свой домен.

**Порядок переключения (cutover):**
1. Собрать и протестировать всё приложение **на системном домене Chatium**.
2. Перенаправить DNS текущего домена BadBuddhas на Chatium + выпустить **TLS**.
3. **Переставить web-app URL Mini App в @BotFather** на новый адрес — иначе Telegram-вход сломается (частая забытая деталь).
4. Обновить: return URL / настройки виджета **GetCourse**, URL коллбэков вебхуков (GetCourse, Telegram), любые ссылки на прод-домен.

> **Уточнить у Chatium:** выпускает ли платформа TLS сама, или нужен свой сертификат от доверенного центра (в т.ч. Минцифры).

## GitHub

Chatium держит код **внутри себя** и **не деплоится из GitHub**. Значит:

- Текущий репозиторий (`badbuddhas-bubbles`) перестаёт быть боевым источником и становится **референс-архивом**: эталон логики, дизайна, медиа, этот handoff-пакет.
- Дайте новому человеку **read-доступ** к репозиторию.
- После того как приложение на Chatium заработает — **заархивируйте** репозиторий (сделайте read-only), но **не удаляйте**: это история и эталон для сверки.
- Новый код (в Chatium) живёт в их web-IDE/проекте; если Chatium поддерживает экспорт/выгрузку кода — настройте регулярный бэкап на свою сторону (страховка от вендор-лока).
